# 08 · 工具脚本使用说明

> 作用：**二十一个脚本**，覆盖 S0–S7 全流程（S0 专业知识预分析 + 5 个校验器 + 统一质量门 + S2/S4/S6 模板 + 辅助工具）。**改文档后必跑校验器，全绿才算完成。**
> 依赖：python 3.8+，标准库即可（无第三方依赖）。
> ⚠️ 这些是**技能包模板**，不是项目脚本。**复制到项目里再改，不要在本包里改。**

## 二、fetch_corpus.py（S1 抓语料）

### 改这几处

```python
BASE = 'https://ixdzs8.com'      # 抓取站（注意：某些子域证书过期，换子域）
BOOK = 503391                    # 书号
LAST_CHAP = 2085                 # 末章
```

### ★ 抓取站的 JS 挑战通用解法（实战总结）

1. 首次请求返回几百字节挑战页，token 形如 `let token = "<base64>"`，
   base64 解码 = `<unix时间戳>:<sha256>`；
2. **该 token 通常不绑路径，可跨页全局复用** → 取一个，所有线程共用；
3. 过一次后服务端下发 session cookie，后续请求连 challenge 都不用带；
4. 每个线程独立 opener（cookie 不共享），但 token 可共享；
5. 并发实测：1 线程 0.1 req/s → 4 线程 0.6 → 8 线程 1.5 → **16 线程 3.2（全成功）**。

### 跑法

```bat
python fetch_corpus.py [起始章] [结束章] [线程数]
```

### ★ 落盘后必跑覆盖率核验（自动执行）

```
落盘章数     : 2085 / 期望 2085
总字符数     : 4267935
缺章         : 无
PUA 乱码字符 : 0（前 200 章抽样）
结论         : ✅ 语料完整
```

**这一步不过，不能往下走。** 语料不全 → 后面所有统计都不可信。

**PUA 乱码检测**：网文站常用私用区字符混淆字体，抽样 200 章统计 `U+E000–U+F8FF`。
秦风项目第一次抓取时就有大量 PUA 未解码（这也是舒英辉 v1 声称全量但没做到的原因）。

## 三、extract_speech.py（S2 台词归属，最关键）

### 改这几处

```python
NAMES = [...]           # 所有会被识别为说话人的名字/别名（含主角）
CONTRAST_ROLES = [...]  # 对照组（**必填**，用于量化污染率）
EXCLUSIVE = {...}       # 排他称呼：'二弟': '某配角'
```

也可用环境变量：`DISTILL_NAMES=甲,乙,丙` / `DISTILL_CONTRAST=乙,丙,丁`

### 四级判定

| 级 | 判据 |
|---|---|
| A | 同行锚定（说话人同在引号行内） |
| B | 引号倒装（引号在前，人名在后） |
| C+ | 纯引号行 + 邻行说话人 + 上下文主语校验通过 |
| C- | 同形态但主语校验不通过（单列说明，不进统计） |

**可靠集 = A + B + C+**

### ★ C 级必须严格

邻行必须**精确匹配说话人**，否则直接剔除。
宽松做法（"任意行含名字就算"）会把可靠集撑大 50%+（实测 5039 → 7632），污染率上升。

### 三步流程

1. 收集原始归属（A/B/C）
2. 排他称呼排除（"二弟""宿主"这类明确属于别人的称呼）
3. C 级上下文主语校验 → C+ / C-，无线索的直接剔除

### 输出

- 各级条数、可靠集条数、唯一台词数
- **对照组污染率**（与对照组可靠集的重叠率）
- **40 条人工抽检样本**（直接列出来让你逐条核对）

★ 两个准确率数字要一起给：**自动污染率** + **人工抽检准确率**。缺一不可。

**实战验证**：本模板用秦风项目跑，逐项复现原项目结果
（可靠集 5039 / 唯一 4304 / A 1462 / B 48 / C+ 3529 / 总字数 4,267,935）。

## 五、measure_purity.py（S2 污染率精确测量）

### 为什么必须有它

`extract_speech.py` 给的污染率是**粗算**（所有重叠都算污染），
里面混着大量"嗯""啊""什么"这种**通用短句**——人人都会说的词，
出现在配角嘴里不算污染。

这个脚本做两件事：
1. **复用同规则的 `collect()`**（`importlib` 动态加载同目录的 extract_speech.py）
   → 保证对照组和可靠集用的是同一套判定规则，**不自写宽松版**。
2. **过滤通用短句**：`len(x) >= 4` 且不在通用短句黑名单里，才算真污染。

### 改这几处

```python
GENERIC = {'什么','怎么','为什么','就是','不是','可以','没有','一个'}
MIN_LEN = 4
```

### 输出

`_stats/污染率测量.json` → 交给 `build_evidence.py` 进人格数据。

### ★ 实战验证

秦风项目用本模板跑 → **真污染率 4.11%**，原项目手算 4.09%，差 0.02 个百分点。

> ⚠️ **别自己重写一套宽松规则去测污染率。** 本次实测教训：
> 宽松版（"任意行含角色名就算归属"）让可靠集从 5039 虚高到 7632（+51%），
> 污染率从 4.09% 暴涨到 26.59%。这是**静默出错**型——不报错，数字全是错的。

## 六、final_stats.py（S4 语言指纹统计）

### 它解决什么

§4「语言方式」是整个提示词最难写的部分，也是最容易**编造**的部分。
不跑统计就写 = 编数字。

这个脚本产出 §4 需要的**全部实测数字**，一次到位：

| 指标 | 产出键 |
|---|---|
| 句长分布 | 均值 / 中位 / p90 / 最短 / 最长 / ≤5字占比 |
| 标点习惯 | ！ ？ …… —— 各出现次数与占比 |
| 自称 | 朕 / 本王 / 寡人 / 咱 / 我 等出现次数 |
| 粗口 | 按脏话词表统计次数 |
| 称呼 | 对他人的称呼用词频次 |
| 复用整句 | 出现 ≥2 次的完整台词 + 次数 |
| 句尾二字 | 高频句尾模式（如"何事""也罢"） |
| 高频短语 | Top N 短语 + 次数 |

### ★ 高频短语的双重剔虚词机制

直接取 Top N 会被**虚词霸榜**——"什么""你们""我们"毫无辨识度，
但频次极高，写进提示词等于没写。

脚本两道过滤：
1. **子串过滤**：A 是 B 的子串且次数接近（`ct >= c * 0.8`）→ 只留长的 B。
2. **虚词黑名单**：命中停用词表的一律剔除。

### 输出

`_stats/语言指纹.json` → §4 数字的**唯一来源**。

### ★ 实战验证

秦风项目跑本模板 → 句长均值 **13.59** / 中位 **7** / p90 **37** / ≤5字 **39.2%**；
复用整句 Top5 = 「呜呜……」×16、「卧槽！！」×12、「什么！！」×11、「阿这！！」×9、「嘿嘿……」×9
—— 与原项目手算**逐项一致**。

## 八、build_evidence.py（S6 证据表 + 人格数据）

### 它做什么

**一次生成两个交付附件**：

1. `<角色名>_数字人_蒸馏证据表_v2.md` — 逐节列出结论 + 对应证据（直引/统计/推断三级标注）
2. `<角色名>_数字人人格数据.json` — 结构化人格数据（顶层 16 个字段）

### ★ 容错设计

`jload()` 在数据文件缺失时**记录并降级**为"（数据未生成）"，不崩掉整个流程。

为什么这么设计：脚本之间是**流水线**，任何一环的数据没生成就全挂，
等于整个项目卡死。降级跑完至少能告诉你**缺哪个文件**，而不是抛一堆栈。

### 改这几处

```python
SOURCE = os.environ.get('DISTILL_SOURCE', '（作品名）')
VER    = os.environ.get('DISTILL_VER', 'v2')
```

### 依赖的输入

`权威口径.json` / `语言指纹.json` / `污染率测量.json` / `事件级履历.json` /
`<角色名>引用核验.json` / `<角色名>自检.json`

## 十一、verify_citations.py —— 核验原理

**滑窗指纹法**：

1. 按【】块解析文档
2. 取该块内、第 N 章标记**之后**、下一个标记**之前**的第一个引号
3. 归一化（去标点空白）后取**长度-10 连续子串**为指纹
4. 在标注章内命中率 **≥34%** 记通过
5. 未通过则全书扫描，定位真实出处

**为什么用滑窗不用精确匹配**：原文常有省略号、多字、错字、标点差异。

### ⚠️ 半角 `]` 会造成跨块错配

`re.compile(r'【([^】]*)】')` 遇到半角 `]` 会跨块匹配，
把第 318 章的引文错配给第 17 章标记，表现为"章号不符"。

→ **全部全角化**。`selfcheck.py` 会专门扫半角 `[` `]` 并报警。

## 十二、fix_stdout.py —— 批量修 stdout 陷阱

### 为什么需要

```python
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')
```
换掉 stdout 后原对象失去最后引用 → CPython 立即 GC → `__del__` 连带 close() 底层 buffer
→ 之后任何 print 抛 `ValueError: I/O operation on closed file`。

**被 import 时最致命**：模块级再包一层，import 方那层当场被 GC，buffer 当场关闭。

### 正确写法

```python
sys.stdout.reconfigure(encoding='utf-8', errors='replace')
```
原地改编码，不换对象、不关 buffer。

### 用法

```bat
python fix_stdout.py <目标目录>
```
批量扫描并改写项目里所有脚本。秦风项目一次修了 21 个。

## 十三、能验什么 / 不能验什么

**能验**：语料覆盖率、台词归属分级、污染率、统计口径、数字对账、
引文查不查得到、格式合不合规、编号乱没乱、表格列数一致吗、占位符清干净了吗；
**语义反没反转**——由 `semantic_check.py`（v2.1）给出**待复核提示**，不是自动判决。

**不能验**（仍要人判）：
1. **像不像这个角色**——语气、价值观、决策逻辑对不对味？
2. **维度全不全**——有壳无肉？
3. **语义反转的最终定性**——`semantic_check.py` 报 `contradicted` 只是线索，要读原文字句自己确认；
4. **归属对不对**——这句在原文里是台词还是内心叙述？

这四项留在 `03_质量门与验收速查卡.md` 的人工判据里，由用户最终拍板。

## 十六、semantic_check.py（S7 语义级校验 · v2.1 新增）

### 为什么必须有它

前三个校验器**全是字面匹配**，都查不出**语义反转**：

| 校验器 | 只能发现 |
|---|---|
| `scan_fabrication.py` | "这句话原文没有" |
| `verify_citations.py` | "章号对不上" |
| `selfcheck.py` | 数字/口径/格式不对 |

秦风项目实测的那条：原文（p300）「想让我**不抓你回去**也不是不可以，不过你得加钱！」
被写成「想让我**帮你**也不是不可以，不过你得加钱！」——
字符串全部命中原文 → 三个校验器全绿 → 交付物带着一个**意思正好反了**的台词进 prompt。

`semantic_check.py` 把档案里的**断言句**（不只是引号，还有结论、性格标签、关系判断、禁忌）
逐条拿去和原文段落做**蕴含判定**，输出三分类：

| 判定 | 含义 | 怎么办 |
|---|---|---|
| `supported` | 原文支持这条断言 | 放行 |
| `contradicted` | 原文**明确相反**（就是语义反转） | **必须人工读原文拍板** |
| `insufficient` | 原文查不到证据（多为【推断】级） | 正常，但要知情 |

### ★ 它是旁路，不是主链

要调模型（本地 Ollama 或 OpenAI 兼容 API），**不要塞进关键路径**。
报出来的 `contradicted` 是**提示**不是判决——语义判定本身有误报，最终仍旧由人拍板。

### 改这几处 / 怎么跑

```python
NAMES            # 主角名 + 别名（检索时给同章节证据加分）
DEF_SECTIONS     # 参与校验的章节，默认 0,1,2,3,7,12,13（只放**事实型**的节）
                 #   排除 §4 统计（已有脚本复现）/ §8 §9 示例编排 / §0.5 §0.6 §10 §11 指令与负面清单
MAX_CLAIMS = 60  # 默认上限，防费用失控；--limit 0 放开
EVIDENCE_K = 4   # 每条断言取几个候选段落
```

> ⚠️ **别把 §10 OOC 负面清单加进来。** 实测教训：第一版默认范围含 §10，
> 163 条里 15 条 `contradicted`，其中 **10 条全来自 §10**——NLI 把
> 「❌ 不要写文艺腔」当成"这个角色不写文艺腔"，去原文里找反例一找一个准。
> **指令不是事实断言。**（脚本另有一道保险：`❌ ⚠️ 🚫` 开头的行无条件跳过。）

```bat
set DISTILL_ROOT=<项目>& set DISTILL_SRC=<项目>\01_语料\chapters
set DISTILL_V2=<项目>\03_交付物\<角色名>_数字人系统提示词_v2.md
set DISTILL_STATS=<项目>\02_核验\_stats
set DISTILL_CHAR=<角色名>& set DISTILL_NAMES=主角名,别名

python semantic_check.py --selftest          REM ① 先反向验证（必做，见铁律 6）
python semantic_check.py --backend ollama    REM ② 本地模型，不花钱
python semantic_check.py --limit 0           REM ③ 全量；有 contradicted 时退出码 1
python semantic_check.py --only-section 0,1  REM 只查指定节
REM 探针条数默认 8；本篇记的 10/12 是 set DISTILL_SEM_SELFTEST_K=12 跑的（条数越多统计越稳，调用也越多）
```

后端 `--backend`：`auto`（默认，先探 Ollama 再退 API）/ `ollama` / `api` / `stub`。
密钥只从环境变量读：`DISTILL_LLM_KEY` 或 `DEEPSEEK_API_KEY` 或 `OPENAI_API_KEY`。

### 输出

`_stats/<角色名>_语义校验.{json,md}`（md 里「⚠️ 与原文矛盾」区块置顶）、
`_stats/语义校验_缓存.json`（按 后端+断言+证据 的 md5 缓存，换后端会自动失效，重跑不重复花钱）、
`_stats/语义校验_反向验证.json`（检出率/误报率明细）。

> ⚠️ **报告写不进去时不会崩**：若 `_stats` 不可写（典型原因见下节"受控文件夹访问"），
> 自动降级写到 `%TEMP%/蒸馏语义校验_<角色>/` 并打印原因。可用 `DISTILL_SEM_OUT` 指定别处。

### ★ 反向验证（`--selftest`）—— 而且探针本身也要验

沿用铁律 6：从原文取真句当"真断言"，用**极性词替换**造"假断言"，两者都判一遍，报
**检出率**（假断言被判 contradicted）与**误报率**（真断言被判 contradicted）。

**这里有个反直觉的坑（实测踩到过）**：探针生成用朴素 `str.replace` 会造出病句——
「是不是」→「是是」、「分不清功法的好坏」→「分不清功法的好好」、「根本没有要出来的意思」→「根本有要出来的意思」。
模型把这些**病句**判成 `supported`，于是"检出率"被压到 62%，看起来像后端不行，
其实是**探针不行（假红）**。所以 `swap_polarity()` 加了 `_degenerate()` 检查：
替换后若产生原句没有的叠字，就不拿它当探针，宁可少造、不造假红。

**得出结论前先看明细**：`语义校验_反向验证.json` 里有逐条真假判定，别只看百分比。

### ⚠️ 它还会误报，而且还不是完全确定的

- **检索会捞错证据**：实测有一条把别的人物段落捞进来当证据，于是判出"矛盾"。所以
  `contradicted` 必须**点开"原文依据"看是不是真的在说这个角色**。
- **同一个后端同一条断言，两次跑可能给出不同判定**（实测「江湖人称秦老六」一次 insufficient、
  一次 contradicted）。`temperature=0` 也不保证逐字确定。所以：**这是待复核清单，不是判决**；
  可疑的条目用 `--no-cache` 重跑一次，两次不一致的直接送人工。

**结论：它的价值在"把 4 条可疑项从 80 条断言里挑出来"，不在"替你把关"。**

### 18.0 distill_gate.py —— 一键总闸（S7 · v2.4）

把能在本机离线跑的校验一次性全跑，按七条铁律汇总成**单一 PASS/FAIL + 风险清单**。

| 分类 | 脚本 | 失败后果 |
|---|---|---|
| **硬阻断** | `selfcheck` / `scan_fabrication` / `verify_citations` / `evidence_linter` | 整体 **FAIL**，退出码 1 |
| 旁路 | `semantic_check` / `groundguard_check` / `speech_crosscheck` / `style_fingerprint` / `nli_lite` / `character_drift` | 仅 **告警**，仍 PASS |

```bat
cd <项目>\02_核验
python distill_gate.py              REM 跑全部离线校验
python distill_gate.py --selftest   REM 验总闸自身（聚合逻辑 + 6 个组件 selftest）
```

- 报告：`_stats\gate_report.json`（字段 `verdict` / `critical_fail` / `warnings` / `results`）。
  ⚠️ 与其它脚本不同，总闸写盘失败是**静默跳过**（控制台输出照常，别只看"报告:"那一行以为自己落盘了；
  受控文件夹访问环境下就是这种情况，见 §十五）。
- **它只是调度器**：不会替你补环境变量。先按 §一 设好 `DISTILL_*`，否则组件会因缺语料/缺档案
  返回非 0，被记成 `missing` / `error`。
- 组件退出码约定：`0` 通过、`1` 有问题、`2` 脚本缺失或崩溃。
- 总闸自身的 selftest **不包含 `semantic_check.py`**（它要调模型），它在项目里单独跑 `--selftest`。

### 18.1 groundguard_check.py —— 第 5 校验器 · grounding 层（S7 · v2.2）

补两格现有校验器都看不见的：

1. **非引号事实断言**（§0/1/2/3/7/12/13 的陈述句）到底有没有语料支撑；
2. **数字量级矛盾**——同单位比值 > 3 倍，或语料里完全找不到的孤立数字。

```bat
python groundguard_check.py                        REM 默认离线 BM25，零成本
python groundguard_check.py --only-section 0,1,2
python groundguard_check.py --limit 200            REM 默认 200 条
python groundguard_check.py --backend groundguard  REM 装了 groundguard 包才走 LLM 层
```

- 环境变量：`DISTILL_GG_SECTIONS`（默认 `0,1,2,3,7,12,13`）、`DISTILL_GG_OUT`、`DISTILL_GG_MODEL`。
- 输出：`_stats\groundguard.json`（`backend` / `sections` / `numeric_issues` / `grounding` / `issue_count`），
  不可写时降级 `%TEMP%\蒸馏grounding_<角色>.json`。
- 退出码：有 `ungrounded` 或数字冲突 → 1。
- **低分不等于造假**：离线 BM25 只算字符重叠，写法一换分就掉，所以弱支撑是**待复核**，不是判决。

### 18.2 speech_crosscheck.py —— 台词归属第二口径（S2 · v2.3）

`extract_speech.py` 用一套规则归属；本脚本用**另一套**（显式 / 倒装 / 冠名）再归一遍，
两套对不上的台词 = **不确定区**，必须人工抽检——这样污染率数字才有可信下限。

```bat
python speech_crosscheck.py
```

- 读 `DISTILL_SRC` 的章节 txt；可选读 `DISTILL_SPEECH_JSON`（`extract_speech` 的产物）做逐条交叉，
  算 `agree` / `disagree` / `disagree_rate`。
- **分母 = 含引号的台词行**（叙述行不参与统计；`attr_heuristic` 仍吃全文，因为倒装口径要看"下一行"）。
  早期版本把整本正文都算进分母，`unassigned` 恒在 97% 左右、退出码永远是 1，指标失去意义——v2.4 已修。
- **引号会先归一化**：语料里的 `“”‘’` 统一转成 `「」` 再匹配（起点/番茄原书用的是 `“”`，
  不归一化会一句都匹配不到）。秦风实测：68,060 行台词 → 归属 55,128（81%），不确定 12,932（invert 51,144 / leading 3,944 / explicit 40）。
- 输出：`_stats\speech_crosscheck.json`（不可写降级 `%TEMP%`）。
- 退出码：**不确定率 > 50%** → 1（提示"归属噪声太大，先抽检再往下走"）。

### 18.3 style_fingerprint.py —— 五维语言指纹（S4 · v2.3）

`final_stats.py` 管"句式/标点/自称/粗口/称呼/口头禅"，本脚本补可量化的五维：

| 维度 | 指标 |
|---|---|
| 句长分布 | 均值 / 中位 / p90 / 标准差 |
| 标点剖面 | 每种标点占比 |
| 风格随机性 | 字符 bigram 的 Shannon 熵 |
| 词汇丰富度 | 字符型 TTR（去重字数 / 总字数） |
| 功能词 | 的/了/是/我/你/他… 每千字频次 |

```bat
python style_fingerprint.py
```

- 输出：`_stats\style_fingerprint.json`，不可写降级 `%TEMP%\蒸馏style_<角色>.json`。
- 找不到语料只 `[WARN]` 并退出 0（不阻断）。
- 用法：给"防 AI 味 / 人设漂移"提供**基线数字**——同一个角色的两份提示词，指纹差太多就是改写过度。

### 18.4 evidence_linter.py —— S6 证据表质量门（v2.3 · **硬阻断**）

专治"推断级伪装成直引"，查三件事：

1. 每条【推断】必须同时带**置信度（高/中/低）**和**出处/章号**，否则 `ungraded_inference`；
2. 证据表必须有「未溯源推测」区块，且要么列项、要么显式写"无"，否则 `missing_block`；
3. 人格数据 JSON 必须合法，且含 `身份` / `性格` / `关系` 至少一个顶层键，否则 `json_error` / `json_keys`。

```bat
python evidence_linter.py
```

- 文件路径：`DISTILL_EVIDENCE`（默认 `03_交付物\<角色>_数字人_蒸馏证据表_v2.md`）、
  `DISTILL_PERSONA`（默认 `03_交付物\<角色>_数字人人格数据.json`）。
- 输出：`_stats\evidence_lint.json`（`issue_count` + 逐条 `issues`）。
- 退出码：有问题 → 1（**这道是硬阻断，gate 里失败就整体 FAIL**）。
- 证据表不存在只 `[WARN]` 跳过，不判失败——但**交付前必须有**，否则等于没做 S6 质量门。

### 18.5 character_drift.py —— 出场权重 + 人设漂移（S2/S7 · v2.4）

七条铁律管"静态正确"，本脚本管"动态一致"：

- **出场权重**：章节数、提及行数、含主角对话行数、每章提及序列（看有没有"消失 200 章"）；
- **人设漂移**：给定 traits 词表，算前段 / 后段频率，后段 ≤ 前段 × (1−0.5) 判**衰减漂移**
  （抓"前期冷酷、后期突然圣母"）。

```bat
python character_drift.py --selftest
python character_drift.py --corpus <语料合并后的单文件.txt> --name 秦风 --traits traits.json
```

- **它是唯一不吃 `DISTILL_*` 的脚本**，全靠命令行参数；`traits.json` 就是一个字符串数组，
  如 `["冷笑", "温柔", "废话"]`。
- 输出：直接 `print` JSON（`appearance` + `drift`），**不落盘**。
- 退出码：有漂移 → 1。

### 18.6 nli_lite.py —— 离线语义矛盾预筛（S7 · v2.4）

纯词典，两类矛盾：**反义对立**（20 对：帮/害、好/坏、生/死…）与**否定翻转**
（断言含否定词，去掉否定和人名后核心谓语仍在证据里 → 极性反了）。

```bat
python nli_lite.py --pairs 待查断言.json
python nli_lite.py --selftest
```

- 输入格式：`[{"claim": "...", "evidence": "..."}, ...]`（也接受 `{"pairs": [...]}`）。
- 输出：stdout 直接出 JSON（`total` / `contradictions` / `hits`），**不落盘**。
- 退出码：有命中 → 1。
- 定位：给 `semantic_check` 当**离线预筛**——先用零成本词典挑出明确极性反转，把要烧积分的调用压到最小。
- ⚠️ **词典匹配必然误报**（"笑" 与 "冷笑" 这类近邻、否定词在长句里的作用域），
  命中一律当**待复核线索**；`DEFAULT_NAMES` 写死 `秦风/林晚`，换项目要改常量。

### 18.7 七个脚本的共同约定

- **纯标准库**，零依赖；每个都带 `--selftest` 反向验证（铁律 6），**先跑 `--selftest` 再信它的输出**。
- 都是**技能包模板**：复制到 `<项目>\02_核验\` 再改常量，别在本包里改。
- 退出码统一：`0` 通过 / `1` 有问题 / `2` 缺失或崩溃（`distill_gate` 按这个分档）。
- 写盘：`groundguard_check` / `style_fingerprint` / `evidence_linter` / `speech_crosscheck` 都有
  "`_stats` 不可写 → 降级 `%TEMP%`"的兜底；根因与修法见 §十五「受控文件夹访问」那条。

### 18.8 professional_profile.py —— S0 七镜头透视骨架（v2.6）

S0 的离线辅助工具。**只做"骨架 + 候选证据行"，不做任何心理/医学判断**；真实分析由 AI 在提示词内完成。

**七镜头**（顺序固定）：逻辑学 / 心理学 / 犯罪学 / 病理学 / 刑侦学 / 测写师 / 经济学。每镜头在脚本里带：
- `dims`：分析子维度（喂 AI 填结论时照着写）；
- `markers`：轻量启发式扫描词（扫全量语料找候选证据行）。

```bat
python professional_profile.py --char 秦风                 REM 只出骨架（md + json）
python professional_profile.py --char 秦风 --corpus <项目>\01_语料\chapters --cap 50
                                                      REM 额外扫候选证据行（章号+行号）
python professional_profile.py --selftest                 REM 验脚本自身（骨架键齐全/扫描不崩溃）
```

- 输出：`<角色>_专业透视档案.md`（七镜头各节占位 + 综合侧写）+ `.json`。
- `scan_markers()` 返回的是**候选**证据行（含标记词的那行），结论仍须 AI 逐条回原文核验——脚本不替你下判断。
- 退出码：0 通过 / 1 有问题（同 distill_gate 分档）。
- **专业框架速查**：`python professional_profile.py --knowledge` 直接打印七镜头可查框架（逻辑谬误表 / 防御机制层级 Vaillant / 依恋类型 Bowlby·Ainsworth / 犯罪学理论 / MOM 三角 / 侧写四要素 / 稀缺、激励、谈判、信息不对称、博弈与制度）；完整框架与核查清单见 **`09_专业知识参考库_S0.md`** 和 **`10_经济学知识参考库_S0.md`**（写 S0 前必读，配套本脚本）。
- **硬约束（与提示词一致）**：① 每条结论挂【直引】/【统计】/【推断】；② 虚构角色不得下真实医学诊断，病理学/心理学镜头只做"文中行为刻画"，必标「【推断·文中表现】」+ 非诊断声明；③ 犯罪学镜头仅当人物有越轨/违法/伤害行为时写，否则标"不适用"，不得硬套。
- 它是**技能包模板**：复制到 `<项目>\02_核验\` 再改常量（如 `LENSES` 的 markers 词表），别在本包里改。
